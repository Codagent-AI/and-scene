# Checklist: create-and-scene

This is a merged verification plan, not a record of executed checks. Original lead IDs (`L-*`) and implementor IDs (`I-*`) are retained together wherever their behaviors overlap; a composite original row may be split across several focused rows. `C-*` rows cover definition details neither checklist explicitly checked. Source describes provenance, not verification status.

References below abbreviate the canonical files under `specs/`; the approved proposal, `design.md`, and `test-plan.md` also apply. Existing rulings in `acceptance-assumptions.md` apply, including “When a non-empty project requires target confirmation before writing”: confirmation precedes any missing-anchor scaffold write in a non-empty project, but adds no gate to an already scaffolded app.

Use fast unit/component/contract tests in `npm test`, scripted commands, and code/file inspection. Skill-procedure checks inspect the actual instructions and their ordering and conditions, rather than merely matching isolated keywords or running an agent through the workflow. Filesystem/detection helpers are tested through their real entry points; documentation-only procedures are inspected and contract-tested. Integration and end-to-end coverage is limited to INT-001, INT-002, E2E-001, and E2E-002 from the test plan. Agent-operated acceptance testing is separate and is not a check in this table. Save command/test output and inspection notes when executing these checks; no row is verified merely by appearing here.
