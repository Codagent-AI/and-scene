# Verification Checklist: create-and-scene

This table merges the original lead (`L-1`–`L-62`) and implementor (`I-1`–`I-50`) checklists. Combined rows cite both original IDs; an original ID can occur in several rows when its behaviors have been separated. `Source` records `lead`, `implementor`, `both`, or `crosscheck` for a behavior absent from both inputs.

These are planned checks, not claims of verified implementation. Unit, component, type-contract, and static-contract tests are fast checks under `npm test`; type assertions must also be compiled, since ordinary Vitest transpilation alone does not check types. The only integration and end-to-end tests planned here are the definition's `INT-001`, `INT-002`, `E2E-001`, and `E2E-002`. Inspection means reading source, styles, templates, or skill instructions; it never means an agent operating the product. Screenshot assertions in INT-002 test artifact/diagnostic mechanics, not visual taste. Actual animation appearance and composition review remain outside this checklist.

References to capability names mean `specs/<capability>/spec.md` in this change. “Inspect SKILL.md” means inspect `skills/presentation/SKILL.md` and its referenced templates. Source inspection accompanies keyword/AST contracts wherever matching a term alone could pass with contradictory instructions. The lead's merge rulings in the run's `acceptance-assumptions.md` retain confirmation for any missing anchor in non-empty targets, the repository-origin attribution URL, replace/remove attribution overrides, and canvas overrides without prescribing an API signature.
