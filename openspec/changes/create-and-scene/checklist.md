# Verification checklist: create-and-scene

Merged from the lead checklist (L-1–L-63) and implementor checklist (I-1–I-61), crosschecked against the approved proposal, design, canonical specs, and test plan. Original IDs in each merged row preserve traceability; an original ID can appear in several rows when its behaviors were separated. Source identifies the originating checklist, with `crosscheck` for uncovered definition requirements.

References below are relative to this change: `evolving` = `specs/evolving-scene-presentations/spec.md`, `presentation-skill` = `specs/presentation-skill/spec.md`, and `verification` = `specs/presentation-verification/spec.md`. Project guidelines refer to the repository's `AGENTS.md`. Existing lead rulings in `acceptance-assumptions.md` resolve target directories, hook names, exact sample strings, and helper defaults; the canonical specs remain authoritative.

This is a verification plan, not recorded execution evidence. Unit, component, type, and contract checks belong to the fast `npm test`/TypeScript layer. Inspection means reading the named procedure, source, styles, or markup; it does not mean an agent operating the product. A keyword match alone cannot prove a procedural rule: inspect its conditions, ordering, and exceptions. Where executable scaffold logic exists, exercise that logic with unit fixtures as well as inspecting the skill. Use only the test plan's INT-001, INT-002, E2E-001, and E2E-002 for integration or end-to-end coverage. Their assertions below strengthen those named tests without creating additional integration journeys.
