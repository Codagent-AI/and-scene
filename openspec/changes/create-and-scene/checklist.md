# Verification Checklist: create-and-scene

Merged from the definition-only lead checklist (L-1 through L-60) and implementor checklist (I-1 through I-52). Original IDs remain in the ID column; an ID may appear more than once when it originally covered distinct behaviors. Source `crosscheck` marks coverage absent from both. These are planned checks, not executed verification; Code, Evidence, and Status are added after implementation and execution.

Capability references abbreviate `specs/<capability>/spec.md`. Repository workflow references use the actual `AGENTS.md`. The lead's three “Merged checklist” rulings in the run output's `acceptance-assumptions.md` select Landing for unknown routes, define scale constancy across steps at a fixed viewport, and require byte-identical kit/script copies with differing outline data outside the scripts. These rulings were checked against the definition; no user decision is pending. Inspection below means source/file inspection, not operating the product. Skill-instruction inspection checks the public contract, not whether a future agent follows it. Only the four integration/end-to-end tests named in `test-plan.md` are planned.
