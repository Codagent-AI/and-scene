# create-and-scene verification checklist

This is a merged verification plan, not evidence of executed checks. Original IDs are retained: `I-` identifies implementor rows, `L-` identifies lead rows, and `X-` identifies behaviors found by crosschecking the approved definition. Combined IDs retain all originating obligations. Source records the behavior’s origin; strengthening a check does not change its source.

Canonical specs control. Definition references are relative to this change directory; source paths and `AGENTS.md` are repository-relative. The lead’s rulings are recorded in `/workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-23T05-38-24-439857939Z/output/acceptance-assumptions.md`. The lead confirmed that same-node persistence applies to shared group/Scene transitions, and that newcomer delays apply only to newcomers; these resolve I-33/L-4 and I-34/L-5 without changing the approved definition.

Unit, component, type-contract and static contract tests are fast checks. Conditional helper tests apply only if that helper ships; otherwise inspect the explicit skill procedure and any implementation performing that operation. No helper must be added solely for this checklist. Inspection reads files or existing records. Component event dispatch and the named browser suites are automated tests; no row requires an agent to operate the product as a user.

Only the test plan’s named integration/end-to-end tests are used: `npm run test:integration` runs INT-001 and INT-002, `npm run verify` is E2E-001, and `npm run test:e2e` runs E2E-002. Fault variants stay within these named tests and use disposable copies without altering the source checkout. Screenshots/warnings test capture and diagnostic mechanics, not automatic aesthetic correctness. Later evidence must reflect checks actually run.
