# Checklist: create-and-scene

Merged verification plan from implementor I-1–I-49 and lead L-1–L-76. Combined IDs retain provenance; repeated verification methods are consolidated without weakening either checklist. Source is `both`, `lead`, `implementor`, or `crosscheck` for definition coverage absent from both inputs.

The approved proposal, design, canonical specs, and test plan control this checklist. Repository guidance is in `AGENTS.md` (called CLAUDE.md in the input checklists). Existing acceptance rulings are in `acceptance-assumptions.md` in the run output; the lead reconfirmed unknown-route handling, present-mode chrome, and target-level anchor detection under “Checklist reconciliation 1–3”. Those rulings resolve the input differences without changing approved requirements.

“Unit” and “contract” checks are fast Vitest checks run by `npm test`; type fixtures are checked by TypeScript. INT-, E2E-, and AT- IDs refer to `test-plan.md`. Browser-backed integration/E2E checks run separately. This is a verification plan: no implementation, Code/Evidence/Status columns, or passing results are claimed.
