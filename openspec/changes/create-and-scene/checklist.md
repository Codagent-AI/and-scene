# Verification Checklist: create-and-scene

Merged from implementor I-1–I-66 and lead L-1–L-80, checked against the approved proposal, design, canonical specs, and test plan. Parenthesized IDs preserve every contributing source row; a source row may be split when it describes distinct behaviors. `crosscheck` rows close gaps in both inputs.

References: `evolving` = `specs/evolving-scene-presentations/spec.md`, `skill` = `specs/presentation-skill/spec.md`, `verif` = `specs/presentation-verification/spec.md`; paths are relative to this change unless stated otherwise. Repository workflow references use the actual `AGENTS.md` (called `CLAUDE.md` in the input checklists).

These are verification obligations, not recorded passing results. No implementation code was read for this merge. Component/hook tests mean fast Vitest tests; contract tests read files. Inspection means inspection of code, configuration, templates, or skill instructions, not an agent operating the product. Tests of skill instructions establish the documented procedure, not proof that an agent follows it. Motion tests establish the structural animation contract, not subjective motion fidelity. Browser-backed coverage is restricted to test-plan INT-001, INT-002, E2E-001 and E2E-002. Screenshots and visual warnings remain advisory; their absence is not a visual-quality pass.

Lead rulings recorded in [acceptance-assumptions.md](/workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-24T13-53-51-583191501Z/output/acceptance-assumptions.md) reconcile the inputs: unknown routes may render Landing **or** a simple not-found view (superseding the Landing-only ruling); the sample permits no forward departures or relocation/resizing of continuing entities, while normative state changes remain allowed; self-verification checks the generated/modified route separately from the reference-sample verification and runs the full scaffolded verification gate at completion.
