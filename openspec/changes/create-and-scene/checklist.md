# Verification Checklist: create-and-scene

References are relative to `openspec/changes/create-and-scene/`: ESP = `specs/evolving-scene-presentations/spec.md`, PS = `specs/presentation-skill/spec.md`, PV = `specs/presentation-verification/spec.md`. Project instructions are in `AGENTS.md` / `CLAUDE.md`. Clarified details follow the lead's recorded `acceptance-assumptions.md` rulings.

Original `I-*` (implementor) and `L-*` (lead) IDs are retained together where behaviors overlap. An original ID can recur when its row covered multiple behaviors. `C-*` identifies definition crosschecks missing from both lists. These are planned checks, not claims that implementation has passed. Unit/component/type/contract tests run in the fast, browser-free `npm test` suite, with compile-only fixtures also checked by `npm run build`. The only integration and end-to-end tests are the test plan's INT-001, INT-002, E2E-001, and E2E-002, under separate scripts. Inspection means examining source, configuration, or skill instructions; it does not mean operating the product or treating screenshots/advisory diagnostics as automated proof of visual quality.
