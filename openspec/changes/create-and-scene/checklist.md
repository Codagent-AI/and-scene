# Verification checklist: create-and-scene

Merged verification plan from implementor I-1–I-57 and lead L-1–L-66. Original IDs are
retained together on combined rows; an ID may recur where its compound behavior is split.
Source is `both`, `lead`, `implementor`, or `crosscheck` (a definition obligation missing
from both inputs). No behavior is marked verified: this table plans checks, not evidence
that they have run. Only this checklist is in scope for this merge.

Unit/component/contract checks run in the fast `npm test` suite. Inspection means reading
code/files and recording the relevant finding, without an agent operating the product.
Only INT-001, INT-002, E2E-001 and E2E-002 from test-plan.md are planned across processes
or in a browser. These named checks are shared across rows, not additional journeys.
Rendered cleanliness does not prove visual composition or animation quality; screenshots
and advisory warnings do not establish an automated visual pass/fail.

Lead rulings were checked against design.md, “Routing + registry” and “Scene kit”, and the
canonical “Persistent grouped scenes”, “Fixed-canvas fit scaling” and sample continuity
requirements: unknown routes may show Landing or not-found; DOM identity is required
within a shared group, with shared-layout/exit configuration across groups; all sample
entities accumulate without moving/removing existing ones; scale changes on resize/mode
change, never step navigation. These rulings amend L-4/L-34/L-46 and clarify I-24/L-22;
none changes an approved requirement or needs a user decision. Each is recorded in the
lead's external acceptance-assumptions.md under its own question heading.
