# Verification checklist: create-and-scene

This is the merged verification plan, not a record of completed implementation checks. Every original lead (L-) and implementor (I-) ID is retained in the ID column; C- IDs identify definition crosschecks absent from both lists. Source identifies provenance, not verification status. Split behaviors may cite the same original ID.

Check types: **Unit/component/contract** = fast Vitest or jsdom checks under npm test, with type-contract fixtures compiled by npm run build; **Inspect** = inspection of the named files or automatically generated artifacts; **Command** = scripted checks judged by exit code/output. The only integration/end-to-end tests are **INT-001**, **INT-002**, **E2E-001**, and **E2E-002** from test-plan.md, in the separate browser-backed npm script. No check requires an agent to operate the product interactively.

References below use **scene** = specs/evolving-scene-presentations/spec.md, **skill** = specs/presentation-skill/spec.md, and **verification** = specs/presentation-verification/spec.md, all relative to this change. Recorded lead rulings are in /workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-19T08-40-23-406888061Z/output/acceptance-assumptions.md. In particular, identical DOM nodes are required within a group sharing both groupKey and Scene; different groups use shared layout identity and presence transitions. This scopes L-4 as the lead explicitly ruled, rather than imposing DOM reuse across distinct scene groups. The design and scene spec independently support this distinction.
