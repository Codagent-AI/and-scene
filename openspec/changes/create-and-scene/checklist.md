# Verification Checklist: create-and-scene

Merged verification plan. All rows are pending execution; no behavior is marked verified by this planning audit. Source identifies the originating checklist(s); combined IDs retain traceability and may recur when an original row covered several behaviors. `C-*` rows cover requirements absent from both originals.

Spec paths are relative to `openspec/changes/create-and-scene/`. Unit/component/contract tests are fast Vitest or TypeScript checks under `npm test`/`npm run build`. Integration and end-to-end checks are limited to **INT-001, INT-002, E2E-001 and E2E-002** in `test-plan.md`; slower/browser-backed suites use a separate npm script. Inspection means reading files or a deterministic static scan. Skill procedure obligations are checked by inspection/contract tests, without operating the product as a user; structural motion checks do not claim pixel-level visual acceptance.

The lead resolved the three disagreements within the approved definition: no-unmount DOM persistence applies within shared group/Scene transitions; effective newcomer delay may equal layout duration; scale is step-independent at fixed viewport/mode but recalculates on resize or mode change. These and the existing hook/mode/gesture/template/diagnostic conventions are recorded in the run output’s `acceptance-assumptions.md`. No requirement change or user decision is pending. Repository-guideline citations use the actual `AGENTS.md` (the originals called it `CLAUDE.md`).
