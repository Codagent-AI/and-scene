# create-and-scene verification checklist

This merges every lead ID (L-1–L-77) and implementor ID (I-1–I-49). Bundled source rows can appear in several merged rows so each distinct behavior retains its check. Source identifies origin; C- rows cover definition behaviors missed by both. These are planned checks, not recorded passing evidence.

Fast unit, component, type, and contract tests run through `npm test`. Browser-backed tests stay separate: `npm run test:integration` covers only INT-001 and INT-002; `npm run test:e2e` covers only E2E-001 and E2E-002. `npm run verify` is the E2E-001 production gate. Those four IDs refer to `test-plan.md`; no additional integration/end-to-end journeys are introduced. Inspection means reading files or captured artifacts, not an agent interacting with the running product. For skill procedures, inspect the actual conditions, order, and instructions; contract tests guard those instructions against regression. Finding isolated keywords is insufficient.

Canonical specs control. Rulings are in `/workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-19T01-19-53-635587334Z/output/acceptance-assumptions.md`. The lead resolved L-27 versus I-19: positive finite available dimensions use the exact fit ratio; MIN_SCALE is only a fallback for unmeasurable dimensions. Scale is constant across steps at a fixed viewport/mode and recomputes on resize. Sample accumulation checks enforce the canonical no-rearrangement/no-redrawing rule, without removal exceptions.
