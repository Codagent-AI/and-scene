# Verification checklist: create-and-scene

This merges the implementor's I-1–I-52 and lead's L-1–L-64. Original IDs are retained in each row; an original ID may appear in multiple rows when its behaviors have been separated. Source records provenance: `lead`, `implementor`, `both`, or `crosscheck` for a definition obligation missed by both. The canonical specs control; existing rulings in `acceptance-assumptions.md` supply the concrete thresholds and hook names referenced below. This is a verification plan, not a claim that checks have run.

**Unit** means a fast Vitest unit or contract test via `npm test`. **Component** means a Vitest/jsdom test; mock Motion to inspect layout/exit props where necessary, but inspect the real Motion wiring too. **Type** means a fixture included in `npm run build` (`tsc -b`), with positive and expected-negative cases. **Inspect** means read the specified files or scripted artifacts and record the observations. **Script** means the command's exit code/output decides the result. Slower filesystem/browser coverage is limited to the test plan's INT-001, INT-002, E2E-001, and E2E-002 and runs separately from `npm test`. Synthesized events in automated component tests are permitted; no check asks an agent to operate the product interactively. Visual review below inspects artifacts captured by the project script. Advisory warnings alone cannot establish visual coherence or become a pass/fail gate.
