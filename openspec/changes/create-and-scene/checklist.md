# Verification Checklist: create-and-scene

This merges every behavior from implementor I-1–I-78 and lead L-1–L-70. Combined IDs preserve provenance; Source is lead, implementor, both, or crosscheck for a definition gap in both inputs. These are planned checks, not executed evidence. Code, Evidence, and Status are added only when implementation checks are run.

References: PS = specs/presentation-skill/spec.md; ESP = specs/evolving-scene-presentations/spec.md; PV = specs/presentation-verification/spec.md. References are relative to this change directory. Repository workflow references use the supplied AGENTS.md instructions (called CLAUDE.md in the input checklists).

Unit/component/contract tests use Vitest via npm test. INT-001, INT-002, E2E-002 and additional automated browser fixtures run via npm run test:integration; E2E-001 is npm run verify. Browser assertions use production builds, Playwright/Chromium, and 127.0.0.1. Additional motion fixtures stay under test directories, outside the production registry, Landing and sample-registration check. Tests drive the product programmatically; no row asks an agent to operate it. Skill workflow checks inspect SKILL.md and templates, with contract assertions for the actual instructions, rather than simulating a live agent session. Screenshots and advisory diagnostics do not establish subjective visual quality.

Two merge ambiguities were referred to lead-agent and independently checked against ESP and PV. The lead appended rulings to the run's acceptance-assumptions.md: exits use fixtures because the normative sample only accumulates entities; continuing entities must not replay newcomer fade-in or delay, while an inert retained Appear wrapper is allowed. No user decision is pending. Other existing rulings in that file supply concrete thresholds below without replacing the canonical requirements.
