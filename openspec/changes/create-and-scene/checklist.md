# Checklist: create-and-scene

Merged verification plan; checks have not been run and no implementation evidence is claimed. IDs retain every lead (`L-`) and implementor (`I-`) source row; repeated source IDs split a compound original behavior without dropping it. `X-` rows cover definition behaviors omitted by both originals. `Source` identifies provenance, not verification status.

**Unit** means fast Vitest unit, jsdom component, type, or contract tests in `npm test`; type fixtures invoke TypeScript and assert its diagnostics/exit status. **Cmd** means a scripted command whose output/exit status decides the result. **Inspect** means reading the named source, templates, or files, not operating the product. Skill procedure checks combine a contract test for explicit instructions with inspection for their meaning and contradictory paths; keyword presence alone is insufficient. Only INT-001, INT-002, E2E-001, and E2E-002 from `test-plan.md` introduce integration/end-to-end checks; run them outside `npm test`. Browser operations below belong to those automated tests, never to an agent-led product journey. Screenshot existence and diagnostic output test helper mechanics; they do not establish visual quality.

References name requirements/scenarios in `specs/<capability>/spec.md`, or sections in `design.md` and `test-plan.md`. Repository workflow references use `AGENTS.md` (the originals called these instructions `CLAUDE.md`). Apply the lead's recorded rulings in the session's external `acceptance-assumptions.md`; specifically, L-11 bans stylesheets in both kit copies, while the whole neutral bootstrap may contain host layout-only CSS without imposed visual defaults.
