# Verification checklist: create-and-scene

Merged verification plan from the lead (`L-*`) and implementor (`I-*`) checklists. Combined rows retain both IDs; an original ID can recur where its behaviors span multiple rows. **Source** records origin, and `X-*` / `crosscheck` rows cover definition behaviors neither original checklist explicitly checked. This is a plan, not a record of executed checks.

**Unit** means a fast Vitest unit, component, type-contract, or contract test in `npm test`. **Inspect** means reading the named code, instructions, or files against the stated assertions, without operating the product. **Script** means a command whose exit code or output decides the result. The only integration/end-to-end tests are the four named in `test-plan.md`: **INT-001** and **INT-002** through `npm run test:integration`, **E2E-001** through `npm run verify`, and **E2E-002** through `npm run test:e2e`. Browser-backed assertions below belong to those named tests. Visual screenshots and helper warnings are advisory artifacts, not proof of visual quality. No product operation by an agent is a checklist check.

References `scene`, `skill`, and `verification` below mean `specs/evolving-scene-presentations/spec.md`, `specs/presentation-skill/spec.md`, and `specs/presentation-verification/spec.md`, respectively. `design` and `test-plan` mean the sibling `design.md` and `test-plan.md`. Repository guidelines are in `AGENTS.md`. Existing lead rulings in the external `acceptance-assumptions.md` resolve unspecified constants and hook conventions; the lead reaffirmed Landing-only unknown-route behavior for L-27 / I-56 during this merge.
