# Verification checklist: create-and-scene

Merged from lead L-1–L-80 and implementor I-1–I-45 against the approved
proposal, design, canonical specs and test plan. Each row cites all contributing
original IDs. Broad original rows contribute to several distinct behaviors.
Source is `lead`, `implementor`, `both`, or `crosscheck` for a missed behavior.
These are planned checks; merging this file does not verify the implementation.

References: ESP = `specs/evolving-scene-presentations/spec.md`; PS =
`specs/presentation-skill/spec.md`; PV = `specs/presentation-verification/spec.md`.
Project rules are in `AGENTS.md` (called `CLAUDE.md` in the original checklists).
Rulings =
`/workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-23T11-57-21-403493184Z/output/acceptance-assumptions.md`.
Its six appended “Merge ruling” sections resolve the input conflicts: resize
recomputes scale; geometry-only CSS is allowed; entry ordering uses `>=`, with
the original strict margin separately retained; a visible mode control is
optional; screenshots/warnings are diagnostic; assumption-derived extensions
are distinguished from canonical requirements.

Unit and component checks mean fast Vitest tests under `npm test`, including
TypeScript type contracts. Inspect means reading named files and recording
findings, not operating the product. Conditional helper tests apply if that
helper ships; otherwise inspect the skill/templates for the same contract.
This checklist does not require shipping helpers just to enable tests.

Only the test plan's named integration/end-to-end tests are used: INT-001 and
INT-002 (`npm run test:integration`), E2E-001 (`npm run verify`), and E2E-002
(`npm run test:e2e`). Fault injections stay in disposable copies. No check
requires an agent to operate the product as a user. Browser visual composition
is checked once in later acceptance testing; the source and diagnostic checks
here cannot establish visual coherence.
