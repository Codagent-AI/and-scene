# Checklist: create-and-scene

This is a verification plan, not a record of completed checks. Original lead (`L-*`) and implementor (`I-*`) IDs are retained together wherever their coverage overlaps; an original ID may appear in multiple rows when it covered multiple behaviors. `C-*` rows add definition coverage missing from both inputs. Source identifies provenance, including `crosscheck` for those additions.

References below use **scene** = `specs/evolving-scene-presentations/spec.md`, **skill** = `specs/presentation-skill/spec.md`, **verification** = `specs/presentation-verification/spec.md`, **design** = `design.md`, and **plan** = `test-plan.md`, relative to this change directory. Project guidelines are in the repository's `AGENTS.md`.

Lead rulings recorded in the run's `acceptance-assumptions.md` clarify L-4, L-10, and L-25: grouped transitions retain scene/entity DOM identity, while cross-scene transitions may replace nodes using shared layout projection; only entity primitives require `layoutId`; scale is constant across steps at a fixed viewport/mode and recomputed on resize or mode change. These corrections follow the canonical specs and design rather than adding API or animation restrictions.
