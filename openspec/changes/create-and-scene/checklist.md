# Verification checklist: create-and-scene

Merged from implementor I-1–I-48 and lead L-1–L-61 against the proposal, design, canonical specs, and test plan. IDs retain provenance; an original row can appear more than once when it covered several behaviors. `crosscheck` rows cover omissions found against the definition. These are planned checks, not recorded verification results.

References below use `scene` = `specs/evolving-scene-presentations/spec.md`, `skill` = `specs/presentation-skill/spec.md`, and `verification` = `specs/presentation-verification/spec.md`, relative to this change. Repository policy is in `AGENTS.md` (the original checklists called it `CLAUDE.md`). Existing [lead rulings](/workspace/home/.agent-runner/projects/-artifacts--runtime-candidate-worktree/runs/audited-implement-change-2026-10-21T06-24-25-673034678Z/output/acceptance-assumptions.md) resolve concrete constants, hook semantics, bootstrap verification, and the present-mode wording disagreement. The lead confirmed that I-11's “only” hides the three named elements, without hiding attribution or imposing a present-mode progress-dot policy.

Use Vitest for the unit, component, and contract checks below. Contract tests of skill prose are backed by inspection of the complete relevant instructions and templates: keyword presence alone is insufficient. INT-001, INT-002, E2E-001, and E2E-002 are the only integration/end-to-end tests planned here. Their fault variants run in disposable copies, preserve the source checkout, and clean up temporary directories and subprocesses. Skill-procedure checks inspect the distributed instructions rather than run an agent through the product. Screenshot checks assert capture/diagnostic behavior, not subjective visual quality.
