# Verification Checklist: create-and-scene

Merged verification plan against the proposal, design, canonical specs, test plan, and repository instructions. IDs preserve traceability to every lead (`L-`) and implementor (`I-`) row; combined rows retain all checks, with stronger assertions where needed. `C-` rows cover definition details absent from both checklists. Source identifies whose checklist supplied the behavior, rather than who proposed a particular assertion.

This table plans checks; it records no completed verification. `npm test` runs fast Vitest unit, component, type-contract, and file-contract tests only. Inspection means reading the named code or files, not operating the product. Browser-backed checks are limited to the test plan's INT-001, INT-002, E2E-001, and E2E-002. Component-test clicks, keys, touches, and resize events are automated assertions. Visual-warning diagnostics are advisory and do not establish visual quality by themselves.
