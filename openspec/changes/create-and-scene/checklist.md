# Checklist: create-and-scene

Specs: `specs/evolving-scene-presentations/spec.md` (ESP), `specs/presentation-skill/spec.md` (PS), and `specs/presentation-verification/spec.md` (PV). Design and test-plan references are relative to this directory. Project rules are in `AGENTS.md` (called `CLAUDE.md` in the input checklists).

Combined IDs preserve every input row: `I-*` identifies the implementor checklist and `L-*` the lead checklist. `X-*` identifies coverage found by crosschecking the approved definition. Source describes provenance, not verification status. This is a verification plan; no row claims checks have already passed.

“Unit” means a fast Vitest unit, component, or contract test under `npm test`; compile-time fixtures must also be included in `tsc -b` via `npm run build`. “Skill contract” means both a Vitest contract test on `skills/presentation/SKILL.md` and inspection of the instructions in context, including conditional precedence; keyword presence alone is insufficient. Component checks use synthetic events, not an agent driving the application. Integration and end-to-end checks are limited to INT-001, INT-002, E2E-001, and E2E-002 from `test-plan.md` and run separately from `npm test`.

At a fixed viewport, scale is invariant across steps within a mode; resize recomputes it. The root gate requires the canonical sample; the scaffold-local gate verifies registered presentations without requiring that sample.
